\section{Reproducibility}

We ran the study from a clean checkout with Python 3.14.7, Docker Engine
29.8.0, Docker Compose 5.5.1, and GNU Make. After starting Docker, we
installed the pinned Python dependencies, ran \texttt{make setup}, and checked
that the replica set had one primary and two secondaries. We then ran the
configuration campaign, followed by the fault campaign and the small matched
mechanism replay. These are the commands at the repository root:

\begin{verbatim}
python3.14 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
make setup
make experiment
make rq2
make rq3-preflight
make rq3
\end{verbatim}

The campaigns record one history per trial. We recomputed the classifications
from those histories with \texttt{make analyse}, \texttt{make rq3-analyse}, and
\texttt{make rq4-analyse} before compiling the PDF. The report figures use
Matplotlib 3.11.2 and SciencePlots 2.2.2~\cite{scienceplots}. Smoke and pilot
runs are optional installation diagnostics; their histories remain separate
from the reported campaign totals.

The repository contains the deployment, schedules, saved histories, and offline
checks. Appendix~\ref{app:install} lists validation commands;
Appendix~\ref{app:full-results} contains the detailed matrices.
