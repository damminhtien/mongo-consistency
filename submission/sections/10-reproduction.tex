\section{Reproducibility}

The archive includes the source tree, raw campaign evidence available at the
build revision, configuration and prediction files, schemas, tests, analysis
scripts, report sources, and a SHA-256 manifest. The artifact map and command
list are also provided in Appendices~\ref{app:repository} and
\ref{app:install}.

For a clean checkout, install the pinned Python dependencies and Docker tooling
recorded for the campaign. The setup target verifies the local tools and
starts the three-member Compose replica set:

\begin{verbatim}
python3 -m pip install -r requirements-dev.txt
make setup
\end{verbatim}

The live validation and experiment commands are:

\begin{verbatim}
make smoke
make pilot
make experiment
make rq2
make rq3
# If interrupted, resume without changing the frozen inputs.
make rq3 RQ3_ARGS=--resume
make rq3-analyse
\end{verbatim}

Smoke validates machinery and is not scientific evidence. Pilot histories are
kept separate from RQ1. RQ1 runs sequentially; RQ2 uses its own campaign
manifest and grouped fault coordinator. RQ3 replays eight matched-seed pairs
for each preregistered contrast and writes separate fault episodes. Main
campaigns require frozen, matching prediction, protocol, and runner provenance
in a clean checkout.

Analysis and report generation use the saved campaign artifacts and do not
require a live database:

\begin{verbatim}
make test
make check-docs
make check-schemas
make rq3-analyse
make analyse
make rq4-analyse
make submission
\end{verbatim}

The first four commands validate and rebuild derived analysis from canonical
raw histories. \texttt{make submission} rebuilds the PDF and filtered
reproduction archive. Run \texttt{make check-release-ready} before upload; it
checks required team metadata in addition to campaign evidence.
