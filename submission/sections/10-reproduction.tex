\section{Reproducibility}

The submitted archive contains the compiled report PDF, the runtime source and
campaign scripts needed to recreate the MongoDB deployment, and the offline
analysis entry points needed to rebuild summaries. The report source, tests,
and raw histories remain in the repository for review but are not part of the
upload archive.

From a clean checkout with Docker running, install the pinned dependencies and
start the three-member Compose deployment:

\begin{verbatim}
python3 -m pip install -r requirements-dev.txt
make setup
\end{verbatim}

The live campaign commands are:

\begin{verbatim}
make smoke
make pilot
make experiment
make rq2
make rq3
\end{verbatim}

Smoke checks the execution machinery and is not scientific evidence. Pilot
histories are separate from the main configuration campaign. The fault
campaign uses its own manifest and groups histories that share one fault
episode.

The offline checks rebuild summaries from saved histories without connecting to
MongoDB:

\begin{verbatim}
make test
make check-docs
make check-schemas
make check-runner-isolation
make analyse
make rq3-analyse
make rq4-analyse
\end{verbatim}

Finally, \texttt{make submission} compiles the manually authored LaTeX source,
adds the data macros derived from the saved summaries, validates the PDF, and
creates the archive containing the PDF, source tree, campaign scripts, and
offline analysis scripts. The manifest records SHA-256 checksums for the
uploaded files. Run
\texttt{make check-submission-artifacts} before upload.
