\section{Reproduction}

The canonical source tree contains:

\begin{verbatim}
configs/            configurations, schedules, predictions, campaign rules
results/raw/        canonical histories and campaign manifests
results/summary/    derived analysis outputs
figures/            plots generated from raw histories
schemas/            versioned record contracts
scripts/            setup, runner, analysis, build, and validation commands
src/                topology, workloads, history, checkers, and analysis
tests/              offline fixtures and harness checks
submission/         LaTeX sources, bibliography, and metadata
\end{verbatim}

Run the offline checks first:

\begin{verbatim}
make test
make check-docs
make check-schemas
\end{verbatim}

The live sequence is:

\begin{verbatim}
make setup
make smoke
make pilot
make experiment
make rq2
\end{verbatim}

The 32-history smoke validates machinery and is not scientific evidence. The
192-history pilot is separate from the sequential RQ1 design of 320 normal
controls and 960 adversarial histories. RQ2 uses its own representative
configuration/fault matrix. The protocol requires frozen prediction and
protocol commits before the pilot and main campaigns.

Analysis and packaging do not require a live MongoDB server:

\begin{verbatim}
make analyse
make submission
\end{verbatim}

Analysis recomputes checkers and summaries from raw histories. Submission
builds the PDF and checksummed reproduction archive from the source available
at that revision. A clean-clone reproduction must use the recorded toolchain
and verify the package manifest before upload.
