\section{Introduction}

\subsection{Problem and objective}

Replicated storage can acknowledge an operation on one member while another
member still exposes older state. The useful question is what the client sees
at the next operation, not only whether the members eventually converge. This
study measures that client view for read-your-writes (RYW), monotonic reads
(MR), monotonic writes (MW), and writes-follow-reads (WFR).

Each history uses one logical document, explicit version dependencies, a fixed
schedule, and an offline checker. A completed history that contradicts its
dependency is a violation. A failed operation or unresolved effect remains
UNAVAILABLE or INDETERMINATE; neither outcome is counted as a pass. The
definitions follow the course slides \cite[slides 37 to 44]{cai-lecture-3}.

\subsection{Questions and scope}

MongoDB is deployed as a three-data-bearing-member replica set in Docker
Compose. The study asks two questions. First, how do read concern, write
concern, and causal sessions affect the four properties under fixed schedules?
Second, how does the same client-visible behaviour change under secondary
failure, primary failover, and network partition? The configuration campaign
uses C1 through C8. The fault campaign uses C1, C3, C4, and C6 and reuses
matching normal controls as a descriptive baseline.

Matched histories explain selected outcomes through recorded routes, operation
times, fault events, and final member state. A separate offline summary reports
completion and latency. These are evidence layers over the two questions, not
additional questions.

Findings are limited to the recorded software versions, schedules, C1-C8
configuration matrix, and single-host container deployment. We did not measure
production availability or behavior across geographically separated machines.
