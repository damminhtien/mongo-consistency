\section{Introduction}

\subsection{Problem and objective}

Replication improves availability and fault tolerance, but replicas can expose
different states while an update is propagating. For an application, the
important question is what a client can observe across successive operations.

We study client-visible behaviour in a three-member MongoDB replica set. We
vary read concern, write concern, and causal sessions while holding each
property-specific schedule and initial document state fixed; every trial uses
a fresh document. Increasing versions make the write and read dependencies
explicit. We examine read-your-writes (RYW), monotonic reads (MR), monotonic
writes (MW), and writes-follow-reads (WFR).

\subsection{Study questions and approach}

The study asks two questions:

\[
Q_1:\quad
\text{How do read concern, write concern, and causal sessions affect these properties?}
\]

\[
Q_2:\quad
\text{How does the behaviour change under node failure and network partition?}
\]

To answer Q1, we state schedule-specific predictions, run normal controls,
then create controlled replica divergence and compare the recorded histories
with those predictions. To answer Q2, we repeat selected settings under a
secondary loss, primary election, and replication-path partition. The normal
controls provide a baseline for interpreting the adversarial results.
