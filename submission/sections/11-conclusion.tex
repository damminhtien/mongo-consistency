\section{Conclusion}

The experiments answer the two study questions in different ways. For Q1,
read concern, write concern, and causal sessions affected the four
client-centric properties jointly rather than independently. The weakest
tested combination allowed all four properties to be violated under controlled
replica divergence. Stronger settings did not always turn those executions
into successful consistent ones; in several cases, the dependent operation
instead timed out or left insufficient evidence for a consistency decision.

For Q2, the type of failure mattered more than failure alone. Secondary loss
and execution after a primary election did not produce violations in the
tested schedules. Replication-path partition was different because it created
a separation between acknowledged state and the state available on the elected
majority side. This was the fault condition in which the differences between
the tested consistency settings became most visible.

The main lesson from these experiments is that client-centric consistency
should not be interpreted only in terms of whether a history contains a
violation. Completion also matters. A configuration may prevent a client from
observing an inconsistent state by delaying or preventing the dependent
operation, so consistency results need to be read together with availability
and decidability.
