\section{Background and formal model}

Let $v$ denote an integer application version allocated by the single logical
writer. A write is written as $W_c(x,v)$ and a read as $R_c(x,v)$. The checker
compares versions and explicit dependencies; response timestamps are used for
latency and diagnosis only. Lamport scalar time can order events but does not by
itself establish the application dependency required by these properties.

\begin{description}
\item[RYW] After client $c$ writes $W_c(x,v_w)$, a later read of $x$ must not
return a version $v_r < v_w$.
\item[MR] For successive reads of the same key by one client, the later
returned version must not be lower than the earlier version.
\item[MW] A successor write must not become visible without its predecessor
under the registered one-document observation.
\item[WFR] A write that depends on a version returned by a prior read must not
be visible without that version.
\end{description}

MongoDB causal sessions track operation and cluster time, but documented
causal guarantees depend on the read and write concerns used by operations in
the session \cite{mongodb-read-isolation,pymongo-sessions}. Causal ON and OFF
both use an explicit session; only its causal-consistency option changes.

The six history outcomes have separate meanings. PASS satisfies the checked
predicate; VIOLATION is a complete counterexample; UNAVAILABLE means an
operation could not be served; INDETERMINATE means a possible mutation or
observation is unresolved; PRECONDITION\_MISS means the schedule did not
establish its required state; HARNESS\_ERROR means the runner or controller
failed. Only PASS and VIOLATION enter the consistency denominator.
