\section{Background and Predictions}

\subsection{Client-centric consistency}

Let \(v\) denote an integer application version allocated by the single
logical writer. A write is \(W_c(x,v)\) and a read is \(R_c(x,v)\). The
properties concern the versions and dependencies observed by the client, not
the order of wall-clock timestamps.

\begin{description}
\item[RYW] After client \(c\) writes \(W_c(x,v_w)\), a later read of \(x\)
must not return a version \(v_r < v_w\).
\item[MR] Successive reads of the same key by one client must not move to a
lower returned version.
\item[MW] A successor write must not become visible without its predecessor
under the experiment's one-document observation.
\item[WFR] A write that depends on a version returned by a preceding read must
not become visible without that version.
\end{description}

RYW and MR are decided directly from values returned to the subject client.
MW and WFR use a one-document post-heal observer to check whether a durable
counterexample remains after the replica set converges. This operationalisation
cannot sample every transient state between a write and recovery, so a PASS
means that the registered durable counterexample was not observed.

\subsection{MongoDB mechanisms}

The experiment varies three mechanisms. Read concern affects which data state a
read may return. Write concern affects when a write is acknowledged. A causal
session carries an operation dependency from one client action to the next.
Read preference and the selected member determine where the scheduled
observation is attempted; the history records the server that actually handled
the request.

\[
\text{read concern}\ \longrightarrow\ \text{which state may be returned}
\]
\[
\text{write concern}\ \longrightarrow\ \text{when a write is acknowledged}
\]
\[
\text{causal session}\ \longrightarrow\ \text{which dependency is carried forward}
\]

These mechanisms suggest different expectations for the four client-centric
properties. The configuration matrix and those expectations are stated before
the method.
