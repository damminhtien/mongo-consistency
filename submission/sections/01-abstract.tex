\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}

MongoDB exposes several controls for consistency, including read concern,
write concern, and causal sessions. These controls are usually described
individually, but an application experiences them together through sequences
of dependent reads and writes. This project studies how their interaction
affects four client-centric consistency properties: read-your-writes (RYW),
monotonic reads (MR), monotonic writes (MW), and writes-follow-reads (WFR), in
a three-member MongoDB replica set.

We designed property-specific schedules that deliberately create replica
divergence, then repeated selected settings under secondary loss, primary
failover, and replication-path partition. Normal executions satisfied all four
tested properties. Under controlled divergence, \texttt{local} reads with
\texttt{w:1} writes and no causal session produced counterexamples for every
property. With \texttt{majority} reads, \texttt{majority} writes, and causal
sessions, the corresponding adversarial histories were not decidable: some
dependent reads timed out and some write effects remained unresolved. Network
partition was the only fault scenario that produced violations in our tests.

Taken together, the results show that consistency controls affect both the
state a client can observe and whether dependent operations can complete. A
run with no observed violation is therefore not necessarily evidence that the
tested property held.
