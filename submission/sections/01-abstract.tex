\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}

This project examines how MongoDB replica-set settings shape what a client
observes from four consistency properties: read-your-writes (RYW), monotonic
reads (MR), monotonic writes (MW), and writes-follow-reads (WFR). We first
varied read concern, write concern, and causal sessions across eight
configurations. We then repeated selected configurations while a secondary
failed, a primary changed during an election, or a replication path was
partitioned.

The configuration campaign contains \NormalHistoryCount\ normal controls and
\AdversarialHistoryCount\ adversarial histories. The normal controls contain
\NormalPassCount\ PASS outcomes and one genuine C7 RYW violation: a write
acknowledged with \texttt{w:1} was followed by a majority read from a lagging
secondary that returned version 0 instead of version 1. C7 has no causal-session
target, so this history is descriptive evidence of a weak dependency rather
than a failed protected prediction. The fault campaign contains
\RQTwoHistoryCount\ histories.

The main result is a change in failure mode. Weak settings can return a
completed stale or reordered value, while majority concerns with a causal
session can leave a dependent operation waiting, timing out, or unresolved
under partition. These observations apply to the recorded MongoDB and PyMongo
versions, schedules, and single-host container topology.
