# DSA5208 project brief

Source: [DSA5208 Scalable Distributed GRP Project](https://docs.google.com/document/d/1X4Lq5Za8d1jb-YOE-K-uBAOfwCax-soaJb-1WFeHJ80/edit), read on 15 September 2026. Use the course document if a requirement here is unclear.

## Goal

Install and test a distributed database with tunable consistency. The project may use MongoDB, Apache Cassandra, ScyllaDB, or another suitable system. The database may run on physical or virtual machines, or in several Docker containers on one machine.

The tests must cover these client-centric properties:

- read-your-writes consistency (RYW);
- monotonic-reads consistency (MR);
- monotonic-writes consistency (MW); and
- writes-follow-reads consistency (WFR).

## Required work

- Work in a group of no more than three people.
- Set up a replicated distributed database.
- Test the consistency settings offered by the selected database.
- Write predictions before collecting or interpreting measurements.
- Design and run experiments that test those predictions.
- Run the experiments during normal operation, after one or more node failures, and during a network partition.

## Submission

Submit a PDF report that covers:

- the database, deployment architecture, software versions, and installation steps;
- the tested consistency settings, their parameters, and expected behaviour;
- the experiment design and its rationale;
- the results and their explanation;
- the difference between observations and expectations, plus the limits of the experiment; and
- the database documentation and every other source used, including any AI use required by the course.

Submit the scripts, source code, and short instructions needed to repeat the main experiments.

## Repository checks

- [ ] Replica-set setup and teardown work from the documented commands.
- [ ] Configuration choices and predictions are recorded before result analysis.
- [ ] Normal, node-failure, and network-partition cases are covered.
- [ ] RYW, MR, MW, and WFR use recorded logical versions rather than wall-clock timestamps.
- [ ] A successful violation is separate from a blocked, timed-out, failed, or unavailable operation.
- [ ] Raw histories, summaries, plots, scripts, source code, and tests are included or generated by documented commands.
- [ ] The final report cites MongoDB/PyMongo documentation, course material, fault-injection tooling, and AI use.
