# Assignment summary

The DSA5208 project installs a distributed database and tests client-visible consistency properties under normal and failure conditions.

## Selected system

MongoDB is the final database choice. The deployment is a three-member replica set in Docker Compose. The experiment pins MongoDB 7.0.34, PyMongo 4.18.1, Python 3.14.7, Docker Engine 29.8.0, and Docker Compose 5.5.1, subject to setup verification and image-digest recording. The MongoDB pin was revised after a direct startup probe showed that the original 8.0.32 image could not run on the Docker Desktop kernel available on this machine.

## Properties

The experiment tests read-your-writes (RYW), monotonic reads (MR), monotonic writes (MW), and writes-follow-reads (WFR). MW and WFR use the same logical document `x` so the dependency is observable in one item.

## Submission

The repository builds a LaTeX report, result tables, figures, raw-history manifest, and reproduction archive. The final package is generated by `make submission` after the tests, campaign, offline analysis, and PDF checks pass.

## Repository requirements

- Record requested and actual member routing for every operation.
- Use explicit sessions for causal ON and causal OFF.
- Disable retry reads and retry writes.
- Keep `PASS`, `VIOLATION`, `UNAVAILABLE`, and `INDETERMINATE` distinct.
- Keep `HARNESS_ERROR` and `UNSUPPORTED` outside database metrics.
- Reject MW and WFR fixtures that use different logical keys.
- Build all summaries from raw histories without requiring MongoDB.
- Keep local tooling and temporary files out of the repository.
