## 1. Project objective

Install and experiment with a distributed database that supports tunable consistency. The database may be MongoDB, Apache Cassandra, ScyllaDB, or another suitable system. It may run on physical or virtual machines, or as multiple Docker containers on one machine.

The project must investigate how database configurations affect the client-centric consistency observed by applications:

- read-your-writes consistency (RYW);
- monotonic-reads consistency (MR);
- monotonic-writes consistency (MW); and
- writes-follow-reads consistency (WFR).

## 2. Group and technical requirements

- This is a group project; each group has no more than three people.
- Set up a replicated distributed database.
- Explore the consistency configurations offered by the chosen database.
- Before running measurements, predict whether each required client-centric model will hold under the configurations selected for testing.
- Design and execute experiments that test those predictions.
- Run the experiments under several scenarios, including normal operation, failure of one or more database nodes, and a network partition.

## 3. Required submission

Submit a PDF report describing the complete project. The report must:

- describe the chosen database, deployment architecture, software versions, and installation procedure;
- describe the consistency configurations explored, relevant parameters, and expected behaviour;
- present the experiment design and rationale;
- report and explain the results;
- compare observations with expectations and identify experimental limitations; and
- cite database documentation and all other sources used, including AI usage.

Also submit the scripts, source code, and brief instructions needed to reproduce the main experiments.

## 5. Repository acceptance checklist

- [ ] Replica-set setup and teardown are reproducible.
- [ ] Configuration choices and pre-registered predictions are recorded before result analysis.
- [ ] Normal operation, node failure, and network-partition scenarios are covered.
- [ ] RYW, MR, MW, and WFR are checked from recorded logical versions, not wall-clock timestamps.
- [ ] Successful violations are distinguished from unavailable, blocked, timed-out, or failed operations.
- [ ] Raw histories, summaries, plots, scripts, source code, and tests are included or generated by documented commands.
- [ ] The final report cites MongoDB/PyMongo documentation, course material, fault-injection tooling, and AI usage.
